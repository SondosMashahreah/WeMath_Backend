# لوحة إدارة محتوى WE MATH — التركيب والاستخدام

- Backend: `8237fb14d0f5e9f96aac7002c727defc6232c56e`

## ما أُضيف

لوحة مستقلة على `/admin` بتصميم عربي RTL، وحسابات خاصة بفريق المحتوى. الأدمن ينشئ لوحات فرعية بأسماء يختارها، ويحدد لكل لوحة الأقسام والأعضاء وإمكانية النشر والأرشفة. يستطيع الشخص الانضمام لأكثر من لوحة. أعضاء اللوحة الواحدة يتعاونون على موادها؛ استخدمي لوحات منفصلة إذا أردتِ عزل أعمال مجموعتين حتى لو كانتا تدخلان النوع نفسه من البيانات.

الأقسام: الامتحانات، أوراق العمل، الأفلام، الأنشطة، الألعاب، القصص والفيديو، الورشات، المسابقات، المبادرات وقصص النجاح، ومكتبة المعلم بتصنيفاتها الحالية.

كل قسم يحتوي نموذجًا فارغًا. موارد الطالب ترتبط بكتاب ودرس من المنهاج الموجود. يمكن إدخال نصوص وروابط HTTPS ومرفقات، وإنشاء أسئلة اختيار من متعدد. يوجد قالب CSV فارغ للموارد وقالب للفعاليات، واستيراد حتى 100 مادة في الدفعة، مع معاينة العناوين قبل تأكيد الحفظ. لا توجد بيانات وهمية تُضاف إلى قاعدة الإنتاج.

تتوفر مسودات، إرسال للمراجعة، نشر، وأرشفة. النسخة المنشورة تبقى كما هي أثناء تعديل المسودة، ولا تتغير إلا بإعادة النشر؛ الأرشفة تسحبها من المنصة. المواد السابقة في أقسام المنصة يمكن نقل إدارتها إلى اللوحات من «المحتوى السابق» مع الحفاظ على روابطها.

الصلاحيات مطبقة في الـAPI، وليست مجرد إخفاء أزرار. يوجد سجل عمليات للأدمن، وفحص إصدار يمنع الكتابة فوق تعديل مستخدم آخر. إيقاف الحساب أو تغيير كلمة مروره يبطل جلساته السابقة. إزالة عضو أو تغيير أقسام اللوحة يطبّق على طلبه التالي.

## 1. تطبيق الباتشين

ضعي ملفي patch بجانب مجلدي `WeMath_Frontend` و`WeMath_Backend`، وافتحي PowerShell داخل المجلد الأب `WeMath`. احتفظي بتعديلاتك المحلية في commit أو نسخة احتياطية أولًا.

```powershell
git -C .\WeMath_Frontend apply --check ..\wemath-frontend-dashboard.patch
if ($LASTEXITCODE -ne 0) { throw "Frontend patch check failed" }
git -C .\WeMath_Backend apply --check ..\wemath-backend-dashboard.patch
if ($LASTEXITCODE -ne 0) { throw "Backend patch check failed" }
git -C .\WeMath_Frontend apply ..\wemath-frontend-dashboard.patch
if ($LASTEXITCODE -ne 0) { throw "Frontend patch failed" }
git -C .\WeMath_Backend apply ..\wemath-backend-dashboard.patch
if ($LASTEXITCODE -ne 0) { throw "Backend patch failed" }
```

إذا ظهر تعارض، توقفي ولا تستخدمي `--reject` أو تعيدي الباتشات القديمة. هذه الرقعة تخص الـcommits المذكورة أعلاه، وليست نسخة كاملة تستبدل مشروعك.

## 2. تحديث قاعدة البيانات وإنشاء الأدمن

داخل مجلد الباك، فعّلي بيئة Python المعتادة. ملف `.env` الحالي يجب أن يحتوي `DATABASE_URL` و`JWT_SECRET_KEY` الخاصين بك. خذي نسخة احتياطية من قاعدة البيانات قبل تحديث مخططها.

```powershell
cd .\WeMath_Backend
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m scripts.create_admin
```

أمر إنشاء الأدمن يطلب اسم مستخدم جديدًا واسمًا وكلمة مرور وتأكيدها. لا توجد كلمة مرور افتراضية، ولا يتم تغيير حساب قائم إلى أدمن ضمنيًا. إذا لديك حساب بدور `admin` بالفعل يمكنك استخدامه دون إنشاء حساب آخر.

التحديث يعيد ملف `app/core/config.py` إلى إعدادات التشغيل الصحيحة؛ النسخة الأخيرة كانت تحتوي كود تخزين يستورد `settings` من الملف نفسه، ولم تكن تعرّف `Settings` أصلًا. لم يُضف ربط تخزين جديد أو مفاتيح خدمات خارجية.

شغّلي الباك بالطريقة المعتادة، أو محليًا:

```powershell
python -m uvicorn app.main:app --reload --port 8100
```

## 3. تشغيل الفرونت

في نافذة أخرى داخل مجلد الفرونت:

```powershell
npm ci
npm run build
npm run dev
```

افتحي `http://localhost:5173/admin`. على الاستضافة استخدمي نفس عنوان المنصة وأضيفي `/admin`، وتأكدي أن الاستضافة تعيد مسارات React إلى `index.html` وأن `VITE_API_BASE_URL` يشير إلى الباك الصحيح. حدّثي الباك وقاعدة البيانات قبل تشغيل الفرونت الجديد.

## 4. إعداد فرق الإدخال

1. افتحي «فريق إدخال البيانات» وأنشئي حسابًا مستقلًا لكل شخص.
2. افتحي «اللوحات الفرعية» واضغطي «لوحة جديدة».
3. اختاري اسمًا، مثل «فريق الامتحانات وأوراق العمل».
4. حددي الأقسام المطلوبة والأعضاء. اتركي صلاحية النشر غير مفعلة إذا أردت مراجعة كل مادة بنفسك.
5. أنشئي لوحة ثانية لفريق الورشات أو المسابقات بالطريقة نفسها.
6. شاركي رابط `/admin` وبيانات دخول كل شخص معه بالطريقة التي تعتمدينها. النظام لا يرسل رسائل أو دعوات تلقائيًا.
7. مدخل البيانات يفتح النموذج، يحفظ المسودة ويرسلها للمراجعة. الأدمن يفتحها من قائمة المواد وينشرها.

لا يحتاج كل موظف موقعًا أو نسخة برمجية جديدة؛ الحساب نفسه يُظهر اللوحات والأقسام المسندة إليه فقط. يمكن إيقاف لوحة أو حساب دون حذف المحتوى.

## 5. إدخال دفعات كبيرة

من «محتوى المنصة»، اختاري لوحة من القائمة وقسمًا من فلتر القسم. نزّلي «قالب CSV فارغ»، واملئيه في Excel ثم احفظيه بصيغة **CSV UTF-8**. لا تغيري أسماء أعمدة القالب. راجعي العناوين المعروضة ثم أكّدي الاستيراد. تُحفظ الدفعة كلها كمسودات أو تُرفض كلها إذا فشلت الصلاحيات أو التحقق، ولا تنشر شيئًا تلقائيًا.

| العمود | المعنى |
|---|---|
| title | عنوان المادة، مطلوب للحفظ |
| summary | وصف مختصر |
| body | النص أو التعليمات |
| source_url | رابط HTTPS للمورد أو التسجيل |
| lesson_id | معرّف الدرس من «دليل معرّفات الدروس» |
| category | رمز التصنيف؛ تظهر الرموز ومعانيها تحت أدوات الاستيراد |
| event_date | تاريخ الفعالية بصيغة YYYY-MM-DD |
| organizer | الجهة المنظمة |
| audience | الفئة المستهدفة |
| location | المكان |
| registration_start / registration_end | بداية ونهاية التسجيل |

أضيفي الأسئلة والروابط المتعددة للمرفقات من نموذج المادة بعد الاستيراد. الحد 100 صف و2 ميغابايت لكل ملف في الواجهة. المواد المنشورة للدرس نفسه تظهر كقائمة موارد داخل نوعها، ولا تستبدل مادة أخرى من الفريق.

## حدود هذه النسخة

- الملفات تُرفق بروابط HTTPS من مكان استضافتها؛ لا يوجد رفع ملفات ثنائية إلى تخزين WE MATH في هذا التحديث.
- أسئلة الامتحان المدمجة تدريب ذاتي مع تصحيح في الصفحة. لا تُسجَّل كعلامات رسمية، وليست نظام امتحانات مراقبة أو بنك إجابات سري.
- النشر لا يرسل إشعارات بريدية تلقائية.
- المنهاج الموجود هو مرجع اختيار الكتب والدروس؛ اللوحة تدير المواد المرتبطة به، ولا تعيد بناء الكتب والوحدات الرسمية. حسابات الطلاب والأهل وملفات التحضير الشخصية للمعلمين تبقى ضمن وظائفها الحالية.
- منصتا PARP وWE STEAM المرتبطتان خارجيًا لا تصبح بياناتهما تحت إدارة هذه اللوحة.

## التحقق

- Backend: `python -m pytest -q`.
- Frontend: `npm run test:student`، `npm run test:cms`، `npm run build`.
- فحص ESLint لملفات لوحة الإدارة الجديدة ومكوّن عرض موارد الدرس.
- اختبارات تكامل حقيقية للـAPI بقاعدة SQLite معزولة: الصلاحيات، الاستيراد الذري، إبطال الجلسة، تعارض الإصدارات، وصول المنشور للطالب، وإدارة المحتوى السابق.
- اختبار React/DOM للوحة: تسجيل الدخول، إنشاء موظف ولوحة، حفظ مادة ونشرها، منع فقد التعديلات، إظهار التعارض، ولوحة مدخل البيانات والمراجعة. HTTP في هذا الاختبار محاكى، وتحقُّق الصلاحيات الفعلي في اختبارات الباك.
- توليد SQL لترحيل PostgreSQL دون أخطاء. لم يُنفَّذ الترحيل على قاعدة الإنتاج.
- تعذر تشغيل فحص Chromium المرئي في البيئة، لذلك لم يُدّعَ إجراء فحص بصري نهائي أو اختبار بحسابات الإنتاج.
